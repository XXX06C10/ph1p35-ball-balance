# brake_precise：先快速制动，再进入35px精准保持

配套使用 `output/brake_precise.bit` 与 `host/start_brake_precise.cmd`。操作流程保持：先把杆调回测量中立姿态，K1使能；球静止在实际中心时按首次K3；再按K2持续回中。再次K2停止并保持，K4立即停止并释放。

## 204902日志结论

上一版已经把高速球较快刹停，但停准仍有两个问题：

- 默认在约90px时就允许进入保持，留下明显中心偏差。
- 当球在约375px偏差处速度降到接近0时，约−19计数的倾角不足以克服静摩擦，电机和目标在约4秒内基本不变；随后短暂回转又触发F2反向反馈保护。

本次只调整外层视觉控制策略。检测、HDMI预测、运动内环、编码器反馈、故障保护、−16°/+32°工作窗口、F1～F8、64脉冲/5秒、500ms丢球与200ms断流均保持原实现。

## 新的停准逻辑

- 高速制动仍使用200px/s目标球速和125ms控制前视。
- 速度降低后继续精确靠近，不再在90px直接结束。
- 只有球进入中心约±35px且估计速度≤12px/s并稳定3帧，才进入回平保持。
- 持续超过±70px或速度升高时退出保持，重新纠偏。
- 若球偏离>35px、速度连续16个真实结果均≤4px/s，说明可能被静摩擦卡住：
  - 80px以内使用约8计数脱困倾角；
  - 80～160px使用约24计数；
  - 160～240px使用约40计数；
  - 240px以外使用约48计数。
- 一旦球开始运动，脱困倾角立即撤除，控制权交回速度制动，避免持续强推。

面板现在同时显示深绿色±35px精准保持带和浅绿色±100px制动区。

## 验证要求

必须通过原18项回归、八组假设动力学模型和原时钟比例交叉验证。相对父版 `brake_fast.bit`，只允许外层视觉控制策略、面板文字与显示带发生变化；核心执行器、故障逻辑、预算、计时、限位、引脚、时钟和串口线格式必须保持哈希一致。

软件和模型通过不等同于实机精度验收。实板测试时轻推球一次后松手，主要观察：

1. 高速时仍能及时制动。
2. 接近中心时不会在90px停下。
3. 进入35px附近后能否稳定回平。
4. 球被静摩擦卡住时是否先轻微增大倾角，再及时恢复制动。

上一版 `output/brake_fast.bit` 保留用于直接对比和恢复；更早的 `region100.bit`、`asym_range.bit` 也保留原哈希。
