# 光照自适应可行性与队友实施任务

## 结论和边界

优先研究“检测 ROI 内稀疏背景采样 + 帧间限速的颜色绝对门限”，维持现有红色优势比例和追踪/聚类逻辑。先证明它能改善识别，再考虑复用现有寄存器写通道实现低速自动曝光。不要新增整帧缓存、完整灰度流水、大规模除法器，也不要先合并两个工程。

本分析基于仓库源码、Logo 原始布局报告以及 precise6 已有验证报告。没有修改 RTL，没有重新综合，也没有实际采集光照数据；所有新增资源都只能列出结构预算，不能给出未经综合的 LUT 数字或保证能放下。

## 实际数据流：与背景描述的区别

以 `merged_vision_motor_logo/user_source/hdl_source/` 为相对路径：

1. `design_top_wrapper.v` 第572行附近：ISP 为 1280×720。第685行附近 `steel_ball_detect` 在 `S_csi_rx_clk` 下读取 ISP 的 128 bit RGB 流，每组三个传输包含5/5/6像素；不是1080p单像素检测。
2. 检测顶层配置 `COLOR_MODE=1`、`COLOR_MIN=45`、`COLOR_RATIO_LOG2=1`、`COLOR_HIGHLIGHT_FILL=0`、`TRACK_EN=1`、`TRACK_COLOR_MIN=35`。它检测红色优势目标，不是简单的“灰度超过200就是钢球”。需确认实物球的涂色和样本是否仍符合该模型；裸钢球不可自动假定适用。
3. `steel_ball_detect.v` 中 `yr/yg/yb → lum`、`rr1/gg1/bb1`、`local_x/local_y`、`local0/local1` 和 `meta0..2` 是可复用的坐标、颜色、ROI与时序路径。亮度路径的表达式是 `(77R+150G+29B)` 的定点结果，但当前颜色分支未必保留这部分硬件：被未使用逻辑优化掉时，再引用会增加资源。
4. `O_color_mask/O_color_meta` 送入 `steel_ball_stream_bbox.v`：ROI、聚类、面积/形状、确认帧和跳变限制产生小球框及有效结果。不得因光照变化直接绕过这些质量检查。
5. HDMI 路径使用 DDR/视频输出，1920×1080；检测坐标按3/2缩放显示。`visual_alg.v` 是 HDMI 域单像素 GRAY/BINARY/SOBEL；顶层 `BINARY_TH=128`、`SOBEL_TH=100`。当前实际灰度是 `R>>2 + G>>1 + G>>3 + B>>3`（最大252），并非文件头注释所写的77/150/29。灰度结果 `s_y1` 可直接用于显示域统计，但位于检测之后，不能直接倒接为摄像头域当前帧检测输入。
6. `mode_switch.v`、`osd_overlay.v`、Logo ROM 和 `ball_info_cdc.v` 属显示/跨域路径；`ball_speed.v` 和 `rtl/vision_monitor_all.v` 内控制速度计算应分别核对，显示速度不等同于控制速度。precise6 的外环、故障/失帧保护和位置中心语义保持冻结。

因此，“修改 visual_alg 的 BINARY_TH”只会改变二值化展示，不会改善现有红色检测。`BINARY_TH`、`COLOR_MIN` 等当前为 elaboration 参数，若要运行时调整，须新增寄存器输入，而非以为已有动态端口。

## 三种方案

| 方案 | 实现及效果预期 | 资源结构预算 | 难度/时序风险 |
|---|---|---|---|
| A：ROI稀疏背景统计，慢速动态颜色门限 | 采样固定背景窗，按背景变化调整45/35附近的绝对门限；保留颜色比例。适于温和亮度变化；不能恢复饱和/欠曝丢失信息，也不能解决所有色温变化 | 一个8位采样、累加器、样本计数、参考/滤波/门限寄存器、ROI比较和帧更新控制；设计目标不新增BRAM/DSP，但须综合确认 | 最低；跨域、高扇出动态门限和像素对齐需检查 |
| B：ROI 16桶粗直方图/分位数 | 背景中位数/高分位比均值更能抵抗少量高光；可估计暗/饱和比例。仍用于颜色门限或曝光统计，而非强行替代颜色分类 |16个计数器，帧间扫描累计、比较、快照或双份桶；可用FF或小RAM，避免六路同桶写冲突；不需要整帧缓存|中等；同地址更新、清桶与新帧竞争、桶选择译码可能成为路径 |
| C：ROI统计驱动传感器曝光/增益 | 使用A或B统计，慢速闭环调整真实曝光，直接影响视频亮度；更贴近官方“自动曝光”示例。强反光、运动模糊和50Hz闪烁需实测 |统计模块外增加控制状态机、寄存器快照/CDC、请求仲裁和超时；尽量复用已有I2C引擎 |最高；主风险是寄存器时序、跨帧生效、反馈延迟及与人工配置冲突，而非新增像素算术 |

A建议固定采样1024个合格像素，则8位值求和只需18位无符号累加器，均值右移10；这是位宽推导，不是综合资源估计。采用确定性空间网格避免只扫到ROI前端；若不足1024样本，整帧丢弃统计，不把不定样本数之和右移当均值。若ROI太小需另设较小的2次幂样本数配置；在帧边界生效。每拍只选择一个实际有效像素，避免六路加法树；检查5/5/6相位，不能选到补零槽。

## 背景、钢球高光和更新策略

统计区域用当前水管 ROI 内的固定背景条带/窗口，避开管边、高亮标记、OSD与Logo；在ISP输出、检测着色叠加之前取样。ROI应先在720p检测坐标下标定，不能把1080p坐标直接使用。

优先固定背景窗，辅以“上一帧可信球框 + 裕量”排除。不能只使用当前二值化未选中的像素作为背景，否则门限错误会污染统计并形成反馈。标记排除、高光裁剪、运动目标和ROI边缘均需独立验证。用面积/置信度、采样有效数及暗/饱和比例决定统计是否可信；异常保持旧门限，超时回退人工固定值并报告状态。

首版采用标定的背景参考B0与当前滤波背景B之差，门限 `T=clamp(T0 + k*(B-B0), Tmin,Tmax)`，k先用移位实现，方向/大小必须用红球与背景样本验证。它不是从背景亮度必然推导出的普适公式。追踪门限保持低于重捕获门限，单独有界；不直接提高颜色比值，也不自动开启高光填充，避免把白色水管误识别。

每帧或每数帧更新：有符号扩展计算差值，IIR可选 `B += (sample-B) >>> 3`，小误差死区、每次最多1～2灰度级、上下限饱和。上述数字是起始实验参数，并非已实测结论。门限在下一SOF一次提交，整帧固定；坏帧不更新。对骤变须记录恢复延迟，不能无限平滑导致一直丢球。目标颜色明显改变时，应先重标定分类器，而非靠背景门限兜底。

## 自动曝光已有通道和缺项

现有 `rtl/vision_camera_control.v` 已包含参数CDC、camera/ROI applied sequence 和 busy 流程，顶层接 `S_ae_req/S_ae/S_ag` 到 `uics500_cfg/uicfgcs500.v`。`uics500regAE.v` 写 `0x3e00/01/02`（曝光编码）、`0x3e08/09`（增益编码）；`SC500GainTbl.v` 是进一步核对增益映射的入口。这些是本代码中的寄存器映射，不能代替传感器手册的生效规则。

后续需取得本相机精确型号/版本的SC500CS寄存器手册、当前uics500reg初始化表对应模式、曝光行单位/最大值/VTS/帧率关系、增益表合法范围、group hold或安全写窗口说明。还须检查 `uii2c.v` 的ACK/重试/读回实现：配置流程完成不等于已读回确认传感器应用。板上SCL/SDA连接、上拉和电平已有接口但需按原理图与实机确认，不能因有端口就认定可靠。

增加自动/手动请求仲裁，手动优先，单笔在途事务，发送后等待完成与若干稳定帧再判断；不逐帧重复发相同设置，不覆盖人工未完成请求。曝光优先、增益其次、限制曝光上限控制运动模糊，按真实帧率与灯光实测防闪烁。暂不改VTS/PLL/MIPI/HDMI时钟。不要同时调曝光和阈值两个快速闭环；先固定阈值调通曝光，或冻结曝光验证A，再以不同时间尺度组合。

## 官方第五项与概念区别

本地《全国大学生嵌入式芯片与系统设计竞赛2026FPGA赛道选题指南-安路科技》PDF第16页（内部页码7），2.5(5)列举自动曝光、白平衡、直方图均衡等ISP处理，以提升环境适应能力。

- 动态阈值：改变检测分类边界，通常不改变显示图像质量，是识别鲁棒性优化，不能直接称作自动曝光。
- 自动曝光：根据反馈控制传感器积分时间/增益，改变采集亮度，更直接对应条目示例。
- 自动白平衡：调节颜色通道关系以减轻色偏；会改变红色优势检测分布，需要联合验证。已有 `isp/awb/` 文件是否启用应按实际层次/网表核实。
- 直方图均衡：重映射像素灰度以改变对比度；全帧当帧映射通常引入额外存储，前帧映射可流式但有滞后，当前不优先实施。

推荐先A改善检测，若争取第五项，进一步C并提供自动调节前后画面/曝光曲线/识别指标。A是否单独满足加分要求须向官方确认，不能保证评分。

## 推荐模块与接口（均为待实现设计）

`ISP RGB + valid/SOF/EOL + existing x/y → roi_background_stats → frame_statistics → adaptive_threshold_ctrl → frame-latched thresholds → existing detector mask → existing stream_bbox → coordinate/velocity/control`。

- `roi_background_stats`：留在摄像头域，输入有效像素8位强度、坐标11位、有效/SOF/EOL、ROI/可信球框；输出 `stats_valid, mean[7:0], sample_count[10:0], bad_frame`。优先直接取现有颜色通道作低成本亮度代理；若使用Y要证明现有路径确实保留且对齐。统计接口为旁路，绝不施加视频背压。
- `adaptive_threshold_ctrl`：同域输入统计、enable/manual_T、标定B0、范围、ROI变更；输出 `pending_color_min[7:0], pending_track_min[7:0], update_valid` 和诊断状态。帧边界写active门限。初始45/35，禁用严格等效原路径。
- `steel_ball_detect`：新增active门限输入替代相应参数比较；同步处理普通/追踪分支，保持mask/meta延迟、颜色比和有效像素数不变。不要改动bbox几何筛选与速度公式来掩盖识别问题。
- `ae_policy`（第二阶段可选）：消费低速统计，通过现有相机参数控制入口提交曝光/增益；需要带序号的CDC握手与仲裁，不能直接跨域传递多位总线。

## 分阶段交付与测试

1. 复现：使用干净基线、相同TD/IP/器件和约束，记录area/全路由setup+hold、时钟报告、关键路径、bit和源哈希。核验Logo聚合源与拆分源是否一致；先别运行compose。当前原始文件路径保留，换电脑需确认工程根路径。precise6的历史报告与当前源是否对应须按提交和哈希核验。
2. 纯统计：先只观测，不改门限和曝光。采集ROI及红球在弱光、正常、强光、侧光、局部高光、遮挡、不同色温及突变条件下的统计分布，确定背景窗、采样网格和有效条件。
3. A独立开关：固定阈值/自适应可切换，复位默认固定，输出当前统计和门限。先仿真，后完整布局布线，再与原相同视频做A/B测试。只有满足约束且指标改善才交付候选bit。
4. 可选C：取得手册后验证单次手动曝光写入和实际画面响应，再固定增益调曝光闭环。观察模糊、闪烁、收敛、传感器帧率和busy超时。单独评估加分项展示。
5. 集成：先冻结检测算法比对同一录制数据的坐标与速度，最后在单独分支集成precise6，保持丢球/陈旧帧/急停/限位保护。相机或图像缩放变更后重新标定。

测试集每种条件至少记录稳定段和光照转换段，建议每段30秒、至少3次重复，包含静止、慢滚、快滚、两端与中心；固定与自适应使用同源视频/相同人工标注，同一曝光设置。自动曝光实机不能只用录制视频验证，要用可重复光源步骤并随机化测试顺序。

指标：有效检测率、误检/漏检率、连续丢失最长帧数、静止中心标准差/峰峰值、相对人工真值的中心误差、速度误差/假速度尖峰、突变恢复帧数；同时记录门限/背景/曝光/增益/ROI/置信度和参数生效序号。不要仅看“框不断”——持续框到背景也是失败。验收阈值应由正常光基线、球尺寸、控制容差确定，当前缺少数据不能宣称已达标。

仿真覆盖：5/5/6像素相位、SOF不伴随valid、提前EOL、行尾不足槽、ROI边界/变更、无样本/不足样本、全黑/全白、球框排除、累加溢出、负差算术移位、上下限、复位/坏帧、帧中禁止换门限、启停回退。验证禁用自适应时mask/meta与原版逐周期一致；检查视频输出所有模式的同步、帧率、总像素数和帧边界。综合后检查新门限高扇出、ROI比较到采样选择、累加器反馈、hist桶写入、跨域CDC及setup/hold；不得放宽约束换通过。

交付队友结果应包括源diff、原版/新版相同工具的资源增量、完整路由报告、原始测试数据与指标脚本、失败条件与回退说明。未经布局布线和实测不能把结构上“无DSP/BRAM”写成最终资源结论。
